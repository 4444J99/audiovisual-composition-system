# ACE directory standardization plan

Scope: the 15 distinct ACE project records in the linked Page, the live audiovisual-composition-system workspace, and observed source repositories. Apply EES naming and boundary principles as an ACE-specific contract; EES controls remain reviewed draft.

1. Read EES, reconcile Page identities and live Git source owners.
2. Repair references broken by the aggregate folder rename without altering worktree contents.
3. Create a small private coordination repository under system; keep the workspace itself non-Git.
4. Define one versioned membership manifest, project-specific profiles, source bindings and old-name compatibility.
5. Generate one directory view for all 15 projects plus repository, component and archive views. Use references to existing authorities; preserve dirty repos and historical bytes.
6. Verify manifest coverage, collisions, link destinations, idempotence, worktree access and unchanged source state.
7. Commit and push the coordination repository; record concrete owners and acceptance predicates for moves needing source reconciliation.

Execution boundary: directory consolidation through aliases and catalogs is authorized now. Source history merges, bulk media transfers, destructive cleanup, public publication and unverified engine extraction are outside this implementation. No new artwork repositories are created merely because a Page exists.
